# 장기 경제와 탐사 기록

2026-11-17. Gemini Windows 앱의 기존 Auto Drill 대화에서 목표·계약 설계 답변을 수신했다.
대화: https://gemini.google.com/u/1/gem/78b48bcfc4c2/c20e1ae511782b11
응답 시 모드 표시는 `4 Hydrogen`이었다. Gemini는 콘텐츠·대안·정책 초안, Codex는 경제 검사·코드 통합·회귀 검증을 맡았다.

## 발견한 문제와 수정

이전 규칙은 같은 낮은 웨이브를 반복해도 선체 +1을 재지급하고, 파츠를 영구 보존하며, 프레스티지 목표는 18 고정이었다.
20시드/1초 단위로 24시간 자동 플레이를 검사한 결과, 균형 모듈 정책에서 환생 횟수 중앙값이 1시간 24회,
6시간 9,023회, 24시간 73,823회였다. 후반 간격은 모델 해상도인 1초까지 내려갔다.
원본 실행 결과는 `tools/reports/long-term-baseline.json`에 보관했다 (미션 도입 전 실행).

- 선체: 최고 기록을 처음 갱신한 4의 배수 웨이브에서만 지급. 과거 획득 파츠는 회수하지 않는다.
- 프레스티지: `18 + 2 * floor(runs / 3)`. 처음 3회는 18, 다음 3회는 20, 다음은 22웨이브.
- 광고/결제로 해금 조건을 건너뛰지 않는다. 첫 합성·첫 환생 수치는 기존과 같다.

## 첫날 미션 범위

Gemini의 추천을 받아 첫 프레스티지 뒤 탐사 기록을 해금한다. 출석, 날짜 변경, 서버, 계정, 광고·구매 조건은 없다.
데이터: `web-prototype/game/expeditions.js`, 진행/수령 상태: `prestige.expeditions`.

영구 목표 7개는 첫 환생, 최고 wave20/30, 스킬15개, 합성5회, 보스10기, 전경 채굴50,000개다.
각 유물 1개를 영구 1회 수령한다. 첫 플레이의 보스·전경 채굴도 집계하되, 첫 환생 전에는 수령할 수 없다.
`totalOreMined`는 오프라인/웨이브 보상도 포함하므로 전경 채굴 목표에 재사용하지 않는다.

| 항해 계약 | 조건 | 보상 |
| --- | --- | --- |
| 과부하 채굴 할당량 | 채굴 모듈로 전경 채굴 2,500개 | 철3, 수정1 |
| 궤도 소탕 작전 | 전투 모듈로 적6기 격파 | 플라스마1 |
| 보스 정밀 타격 | 균형 모듈로 보스2기 격파 | 광석150 |

Gemini 원안의 적40기/보스3기/광석450 보상은 짧은 항해 길이에 맞춰 조정했다.
계약은 각 항해에서 종류별 한 번 수령하고 다음 환생 후 다시 도전한다.
원안의 수령 즉시 무제한 재시작은 채굴 계약 재료가 영구 파츠로 전환되는 점을 고려해 채택하지 않았다.

모듈 전환은 이전 진행도를 소급해서 채우지 않는다. 실제 해당 모듈을 적용한 채굴 틱/격파 이벤트만 반영한다.
처치는 격파 시점의 모듈 기준이며 피해 기여도 계약은 아니다. 10초 전환 대기 중에도 현재 적용 모듈은 유효하다.
광고·미션·오프라인 보상은 계약을 진행시키지 않는다. 진행도는 목표값에서 멈추며 초과분은 다음 항해에 이월되지 않는다.
미수령 계약도 환생 시 초기화되고 UI에서 이를 안내한다. 영구 목표 수령 기록/누적 통계는 유지한다.
구형 저장은 확인 가능한 환생/스킬/엔진/최고 기록을 그대로 사용한다. 과거 보스·전경 채굴 수치는 추정 복원하지 않는다.
로컬 저장 변조/기기 시계 조작/여러 앱 인스턴스 간 경쟁을 서버로 막는 기능은 제공하지 않는다.

## 실행 결과

`npm run balance`: 시드1~20, 0.25초 단위, 광고 없이 가능한 즉시 가챠/합성.
첫 가챠20초, 첫 합성218초, 첫 환생 해금770.75초 중앙값 유지.
연구소 사용 시 첫 환생 해금 중앙값도 채굴792.5/전투703.25/균형748.25초로 유지된다.

`npm run balance:long`: 시드1~20, 1초 단위, 24시간. 구매와 모듈 강화, 탐지기→안정화 연구를 즉시 실행.
미션 정책은 보상을 가능한 즉시 수령. 파츠·스킬 뽑기와 재료 난수는 같은 실제 런타임을 사용한다.
표는 항목별 상위 중앙값이며 한 사람의 기록이 아니다. 모델의 전경 플레이는 24시간 끊임없이 조작하는 가정이다.

| 정책 | 1시간 환생/최고 wave | 6시간 환생/최고 wave | 24시간 환생/최고 wave | 영구 연구 모두 완료 중앙값 |
| --- | --- | --- | --- | --- |
| 채굴, 해금 즉시 환생 | 9 / 22 | 30 / 36 | 46 / 48 | 6,311초 |
| 전투, 해금 즉시 환생 | 10 / 24 | 32 / 38 | 48 / 48 | 5,920초 |
| 균형, 해금 즉시 환생 | 10 / 24 | 30 / 36 | 47 / 48 | 6,151초 |
| 균형, 최소 wave30까지 탐사 | 1 / 30 | 24 / 32 | 47 / 48 | 14,199초 |
| 균형 + 미션 수령 | 10 / 24 | 30 / 37 | 47 / 48 | 5,262초 |
| 균형 + 미션, 5분씩 6회 접속 | 0 / 11 | 1 / 18 | 8 / 22 | 24시간 내 완료 0/20 |

짧은 접속은 0/4/8/12/16/20시간에 각 5분 플레이하고, 나머지는 채굴만 오프라인 정산한다.
미접속 중 구매/합성/연구/미션 수령/전투는 하지 않는다. 1/6/24시간 스냅샷을 위해 오프라인 구간을 나눠 정산한다.
연속 정책의 가장 짧은 환생 간격은 전체 시드/정책에서176초. 짧은 접속 정책은 오프라인 축적 효과로 최소95초였다.
각 정책에 환생 간격60초 이상, 24시간200회 미만, 재화·체력 유한성 및 비음수 검사도 둔다.
현재 전체 결과: `tools/reports/long-term-balance.json`. 빠른 개발용3시드는 `node scripts/simulate-long-term.mjs --quick`.

`npm run check`에 보상 중복/잠금/미달/오프라인 제외/모듈별 집계/환생 초기화/구형 및 비정상 필드 세이브 검사를 포함한다.
브라우저에서는 첫 환생→해금→유물 수령→재접속 후 수령 완료 유지와 작은 화면 표시를 확인한다.

## 남은 판단

시뮬레이션은 리텐션 실험이 아니다. 자동 연속 플레이에서는 영구 연구가 약1.5~4시간에 소진되고,
24시간 시점 마지막 환생 간격이 약1~2시간까지 길어지는 정체가 남는다. 단기 접속은 진도가 훨씬 느리다.
현재 미션은 첫 콘텐츠 묶음이며, 추가 보스 패턴·모듈별 도전과 실제 사용자 세션 결과로 후속 범위를 정해야 한다.
서버/분석 SDK/푸시/일일 리셋은 이번 단계에서 추가하지 않았다.
