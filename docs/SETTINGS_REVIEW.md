# 설정·도움말과 접근성 검증

2026-11-17. Windows에서 효과음 음량과 수동 모션 줄이기, 다시 읽는 도움말을 구현했다.
작업 범위가 저장/오디오 오류 처리와 UI 통합 중심이라 이번에는 Gemini에 별도 위임하지 않았다.

## 현재 동작

- 언어 선택은 자동/한국어/English/日本語다. 구형 세이브는 자동으로 이전하고 백업/복원 시 유지한다.
  주요 화면의 공통 키 247개를 연결했으며 나머지 동적 콘텐츠·SDK 문구는 `LOCALIZATION_PLAN.md`에 남겼다.

- `설정 · 도움말`은 효과음 사용, 음량 0~100%(5% 단위), 미리 듣기와 모션 줄이기를 제공한다.
- 미리 듣기 선택은 일반/SR/UR 뽑기·합성·보스·환생·연구·보상·장착의 9종이다.
- 외부 샘플 없는 합성음이며 동시 발음은 16개로 제한한다. 새 음색/선택 UI의 iPhone 청음은 미완료다.
- UMP가 요구하고 네이티브가 지원할 때만 광고 개인정보 선택 버튼을 표시한다.
  JS 차단/오류 분기는 자동 검사했으며 실제 동의 화면은 Mac 네이티브 검증이 남았다.
- 새 설치는 효과음 끄기·음량 50%·수동 모션 줄이기 끄기다. 기기의 모션 줄이기가 켜지면 항상 따른다.
- 수동/기기 모션 줄이기는 함선 회전과 격파 파동, 버튼 눌림 이동을 멈춘다. 채굴·전투 수식과 보상은 같다.
- 기존 음소거 버튼은 유지한다. 음량 0%에서 빠른 켜기를 누르면 음량 50%로 복귀한다.
- 게임 효과음의 음량만 조절한다. 네이티브 광고 소리는 광고 화면/기기 음량의 영역이며 제어했다고 표시하지 않는다.
- 도움말 5개는 성장·연구소·환생 유지/초기화·보스/연계·오프라인/백업을 설명한다. 읽는 동안 게임은 진행한다.
- 설정창을 열면 위쪽 음량 조절부터 보이고, 닫기와 Escape를 지원하며 원래 버튼에 초점이 돌아간다.
- 기본 HTML 체크박스·범위 입력·접기/펼치기·dialog를 사용한다. 음량에 숫자 표시와 접근 가능한 이름을 붙인다.

`settings`는 `soundEnabled`, `soundVolume`(0~1), `reduceMotion`을 저장한다.
기존 `soundEnabled`만 있는 저장은 음량 0.5와 모션 줄이기 false를 채운다.
유한한 숫자만 음량으로 받고 0~1로 제한한다. 백업·복원과 프레스티지 후에도 설정을 유지한다.
기기 모션 줄이기 여부는 실행 중 확인하며 백업에 기기 환경을 복제하지 않는다.

오디오는 사용자 입력 전 AudioContext를 만들지 않는다. master gain으로 재생 중 음량을 적용하고,
무음/중단 시 예약된 소리도 중지한다. 지연된 AudioContext 재개가 음소거/백그라운드 이후
도착하면 이전 소리를 재생하지 않는다. 오디오 API가 없거나 재개에 실패해도 플레이를 계속한다.

## 확인한 범위

- `npm run check`: 구형/손상 설정, 범위 제한, 백업 왕복, 게임 경제 불변, 시스템/수동 모션 정책,
  실시간 master gain과 지연 오디오 취소를 포함해 통과했다.
- `npm run build`: 정적 앱 번들 생성 통과.
- 브라우저 390×844, 320×740, 844×390에서 설정창 가로 넘침이 없었다.
- 음량 35%와 모션 줄이기 재시작 유지, 음량 0% 미리 듣기 비활성, 빠른 켜기 50% 복귀를 확인했다.
- 키보드로 음량 조절, Escape 닫기와 초점 복귀, 도움말 펼치기를 확인했다.
- 실제 UI에서 생성한 백업에 설정이 포함되고 이전 백업 복원 시 설정이 되돌아오는 것을 확인했다.
  테스트용 별도 로컬 주소에서 수행한 뒤 기존 저장을 복원했다.
- `mobile-settings-preview.jpg`는 이전 QA 중 음량 35%·모션 줄이기 상태의 화면이다.
  이후 추가한 9종 미리 듣기 선택 UI와 UMP 진입점의 화면 검증 자료는 아니다.

브라우저 검사와 가짜 오디오 장치를 사용한 단위 검사는 iPhone 음질·실제 기기 볼륨·무음 스위치·
블루투스/통화 중단·VoiceOver 사용성·Dynamic Type·전체 접근성 적합성을 증명하지 않는다.
진동은 아직 연결하지 않았다. Mac에서 네이티브 지원/플러그인과 실기기를 확인한 뒤 구현한다.

## 신규 사용자 플레이테스트 진행표 (아직 사람 대상으로 실행하지 않음)

한 명당 15~20분 동안 조작을 지시하지 않고 다음을 관찰한다. 시간은 예측이 아닌 관찰값으로 적는다.
첫 세션은 초기 저장으로 시작하되 기존 사용자 진행은 먼저 백업한다.
제3자 전송이나 분석 서버는 추가하지 않았다. 참여자 실명 대신 임의 번호를 사용해 로컬 메모로 기록한다.

| 관찰 지점 | 기록할 내용 |
| --- | --- |
| 시작~첫 뽑기 | 자동 채굴을 이해했는지, 첫 뽑기까지 시간, 막힌 지점 |
| 첫 합성 | 철/수정 필요량과 합성 효과를 설명할 수 있는지, 소요 시간 |
| 연구소 | 모듈 1개 활성·전환 10초·항해/영구 차이를 이해하는지 |
| 첫 환생 선택 | 남는 것/사라지는 것을 예상하는지, 누르기 전 불안·혼동 |
| 설정/도움말 | 음량을 줄이고 도움말을 찾아 읽을 수 있는지, 글자/터치 불편 |
| 종료 | 계속 하고 싶은 이유·그만두고 싶은 이유·가장 헷갈린 것 각 1개 |

후속 세션 또는 별도 QA 저장으로 보스 단계/연계·항로 목표를 확인한다. 이 결과를
신규 설치 첫 세션 결과와 섞지 않는다. 표본 수, 기기, 실행 버전과 실제 실패 사례를 함께 적고,
단일 사용자 반응만으로 리텐션/수익 개선을 확정하지 않는다.
