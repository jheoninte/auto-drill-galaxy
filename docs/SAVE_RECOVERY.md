# 로컬 저장과 복구

2026-11-17 Windows 구현. 자체 서버/계정/자동 클라우드 동기화 없이 동작한다.

## 플레이어 흐름

상단 `저장 · 백업 / 복원` → `현재 진행 백업 만들기` → 전체 코드를 메모나 파일에 복사한다.
다른 기기 또는 복구할 앱에서 전체 코드를 붙여넣고 `복원 내용 확인`으로
웨이브/환생/스킬/암흑물질 요약을 확인한 뒤 `복원 적용`을 누른다.
현재 진행을 교체하며, 적용 직전 진행은 `복원 전 백업 확인`으로 확인/되돌리기 할 수 있다.
복원 전 슬롯은 복원할 때마다 갱신되므로 중요한 코드는 별도 보관한다.

유료 상품 권한은 코드에 포함하지 않는다. StoreKit 검증 및 상점의 구매 복원을 이용한다.
브라우저에서 구매 성공을 흉내 내지 않는다. 자동 클라우드 이전이나 앱 삭제 후 복구를 보장하지 않는다.

## 형식과 보존

- 기본 키 `auto-drill-galaxy-save-v2`는 유지한다. 기존 raw v2 데이터는 읽은 뒤 포장 형식으로 이전한다.
- 포장: `{format:"auto-drill-galaxy",version:1,checksum,payload}`. payload는 JSON 문자열이다.
- FNV-1a 검사값은 우발적 손상 검출용이며 암호화/위변조 방지 서명이 아니다.
- `PROGRESSION_SCHEMA.json`의 성장 축을 유지하며 session은 매 실행 초기화한다.
- whitelist를 통해 알려진 데이터만 저장한다. 숫자는 유한·음수 방지, 파츠/재료/횟수는 정수로 정규화한다.
- 웨이브는 손상 데이터로 인한 HP 지수 폭주를 막기 위해 읽을 때 1~1000으로 제한한다. 목표 콘텐츠 범위를 훨씬 넘는다.
- HP 0을 그대로 보존하며, 최대 체력이 바뀐 구버전은 남은 체력 비율을 이전한다.
- 기본 자동 저장 5초, 성장 행동 및 백그라운드 진입에도 저장한다.
- `-backup`: 직전 정상 기본 저장. 기본이 손상되면 자동 복구한다.
- `-recovery`: 최초 손상 원문, 또는 명시적 복원 전 기본/자동 백업 원문 묶음. 자동 덮어쓰기하지 않는다. 개발자 진단용이다.
- `-before-restore`: 플레이어가 마지막으로 복원 적용하기 직전의 실행 진행. UI로 다시 확인 가능하다.
- 기본/백업 모두 손상되었거나 저장소 접근이 거부되면 새 임시 플레이 상태에서 경고를 유지하고 자동 저장을 차단한다.
  원본을 보존하며 정상 백업 코드의 명시적 복원으로 저장을 다시 시작한다.
- 미지원 버전 기본 저장은 오래된 자동 백업으로 대체하지 않는다. 최신 앱 확인을 안내한다.
- 저장 실패 시 성공 시각을 기록하지 않는다. 복원은 이전 진행 보존과 기본 쓰기가 모두 성공한 후 메모리 상태를 교체한다.
- 기본 슬롯 쓰기는 localStorage setItem 단위로 원자적이지만 여러 슬롯 전체의 트랜잭션은 아니다.
  보조 슬롯 실패 시 기본 쓰기를 중단한다. 여러 창에서 동시 플레이하는 병합/잠금 기능은 없다.

## 오프라인과 복귀

읽은 저장의 오프라인 채굴을 정산하고 즉시 저장하여 재실행 중복을 줄인다.
백그라운드 진입 시각/스탯을 한 번 캡처한다. visibilitychange/pagehide 중복에도 같은 스냅샷을 사용한다.
복귀는 해당 스냅샷의 채굴량으로 최대 4시간, 전투/계약 진행 없이 1회만 정산한다.
중간 SDK 저장이나 모듈 상태 변경이 보상을 바꾸지 않는다. SDK 요청 중 진입/복귀한 구간은 보상에서 제외한다.
pageshow도 처리하여 BFCache 복귀를 지원한다. 실제 WKWebView suspend/kill 동작은 Mac 검증 대상이다.

수동 백업 복원은 저장된 과거 오프라인 시간을 보상하지 않고 현재 시각으로 저장한다.
광고 지급 ID 최근 기록과 쿨타임은 현재/가져온 데이터 중 더 엄격한 기록을 유지한다.
게임 저장/기기 시계는 신뢰할 수 있는 서버 검증이 아니다. 옛 백업으로의 의도적 되돌리기,
기기 간 복제, 저장 실패 중 강제 종료의 중복/유실까지 차단하지 않는다. 경쟁·금전 보상 기준으로 사용하지 않는다.
