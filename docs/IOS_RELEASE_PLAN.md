# iOS 우선 출시 계획

## 제품과 기술 방향

Windows에서 Gemini와 Codex로 게임 로직·UI·밸런스·콘텐츠를 개발하고 Mac mini에서
네이티브 연동·실기기 검증·서명·TestFlight·스토어 제출을 진행한다.
기본 무료 IAP + IAA 하이브리드 캐주얼 게임이며, 첫 버전은 계정과 자체 서버 없이 동작한다.
기존 HTML5 게임을 Vite로 번들하고 Capacitor로 패키징한다. 엔진 재작성 비용을 줄이는 선택이며,
장시간 플레이의 발열·프레임·메모리는 iPhone에서 측정해 판단한다.

## 첫 버전 수익화 구현 정책

출시 수량·언어·비주얼의 기준은 `RELEASE_SCOPE_V1.md`, `VISUAL_ASSET_PLAN.md`,
`LOCALIZATION_PLAN.md`다. 하루 2회 5~8분 × 약 30일, 구역 5개/신규 캠페인 과제 30개를
목표로 확정했다. 5구역/30과제와 추가 콘텐츠를 통합하고 표준 30일 모델 20시드 완주를 확인했다.
실제 재미/리텐션과 한국어·영어·일본어의 원어민·iPhone 검수는 진행 전이다 (`LAUNCH_CONTENT_REVIEW.md`).
아래 광고 정책은 JS에 적용하고 광고 시간을 포함한 30일·정책별 20시드 모델로 비교했다 (`MONETIZATION_REVIEW.md`).
실제 SDK 연동·시청률·리텐션·수익 검증은 남아 있다.

- 보상형 광고: 첫 합성 또는 환생 후 선택형 보급. 요청 때 120초 채굴량과 다음 뽑기 비용 20% 중 큰 값을 미리 표시, 완료 콜백에서만 지급, 완료 후 5분 대기
- 전면 광고: 프레스티지 보상 안내 뒤에만. 앱 실행 후 전경 10분 제외, 전경 8분 간격, 실행당 2회. 보급 후 2분 보호·실패 재시도 60초·환생 기회 15초
- 광고 제거: 비소모성 IAP. 자동 전면 광고만 제거하고 선택형 보상 광고 유지
- 서포터: 비소모성 IAP. 전용 함선 색상, 게임 성능 차이 없음
- 가격: App Store Connect 설정 후 StoreKit의 현지화 가격만 표시. 현재 ID는 임시
- 초기 현금 재화 판매/유료 랜덤 뽑기는 보류. 현재 뽑기는 플레이로 얻는 광석만 사용

광고 배치는 리텐션과 수익 실험의 후보이며 효과가 입증된 값이 아니다.
강제 광고 빈도보다 첫 세션 이해도·성장 선택·프레스티지 동기를 먼저 검증한다.

## 서비스 선택과 비용

2026-11-17 공식 안내 확인 기준이며 결제 통화·세금·계약 조건은 가입 시 확인한다.

| 항목 | 첫 출시 선택 | 비용과 한계 |
| --- | --- | --- |
| 게임 실행/진행 저장 | 앱 번들 + 로컬 세이브 | 자체 서버 비용 0. 삭제·기기 변경 시 진행 복구 보장 없음 |
| iOS 배포 | Apple Developer Program | 연 99 USD, 지역별 가격 상이 |
| IAP | StoreKit 2 직접 연결 | 별도 SaaS 월 요금 없이 구현. 스토어 수수료 발생 |
| 소규모 사업자 | App Store Small Business Program 신청 검토 | 자격 충족·승인 시 유료 앱/IAP 수수료 15%. 자동 적용 아님 |
| 광고 | AdMob 단일 네트워크 후보 | 자체 광고 서버 불필요. SDK·동의·광고 정책·정산 설정 필요 |
| 리더보드 | 처음에는 제외, 필요 시 Game Center | Apple 계정·플랫폼 기능 활용. 별도 자체 서버 없이 가능 |
| 클라우드 저장 | 첫 버전 제외 | 구매 복원은 게임 진행 복원과 다름. 필요 시 iCloud 등 별도 검토 |
| Firebase | 첫 버전 미사용 | Spark는 무료 한도 안에서 사용, 제품별 지원/한도 다름 |
| Android 배포 | iOS 이후 | Google Play 등록비 25 USD 1회, 기타 정책·수수료 별도 |

무료 한도를 넘기는 공용 크로스플랫폼 랭킹이 필요해지면 우선 조회 빈도/기록 보관량을 줄이고,
실제 DAU·쓰기/읽기 수·트래픽으로 Firebase Blaze 종량제 비용을 산정한다.
Blaze 예산 알림은 결제를 자동 차단하는 상한이 아니다. 플랫폼별 순위면
Game Center와 Play Games Services를 나누어 쓰는 방식이 서버 운영비를 최소화한다.
현재는 공용 랭킹의 필요성과 사용량이 정해지지 않아 고정 월 비용을 제시하지 않는다.

## 로컬 세이브와 신뢰 경계

- 구매 권한은 게임 세이브에서 해금하지 않고 네이티브 StoreKit 검증 결과로만 적용
- 비소모성 구매는 복원 버튼 제공. 오프라인 권한은 네이티브가 검증한 캐시로 처리
- 환불·취소·미승인 구매·지연 거래·재설치·스토어 계정 변경 처리를 Mac에서 구현/검증
- 광고 완료 및 광고 1회 식별자는 SDK가 전달. JS 보상 중복 방지는 제한된 최근 기록을 사용
- 클라이언트 세이브와 기기 시간은 조작 가능. 경쟁 보상이나 현금성 지급 기준으로 사용하지 않음
- 처음에는 순위 기반 보상을 제공하지 않음. 경쟁이 중요해지면 서버 검증 비용을 재검토
- 앱 코드/SDK는 번들에 포함. 게임은 네트워크 없이 진행되고 광고/결제 장애는 플레이를 막지 않음

## Gemini / Codex 분업

Gemini: 긴 기획 비교, 튜토리얼/스킬/보스 콘텐츠 묶음, 경제 곡선 후보, 현지화 초안.
답변은 범위가 정해진 CSV/JSON과 계산 가정을 요청한다.
Codex: 실제 수치 시뮬레이션, 모듈 통합, 저장/광고/구매 오류 처리, 빌드와 회귀 검증.
Gemini의 SDK 예시나 추정치는 그대로 출시 코드로 채택하지 않는다.
