# 광고 보상·노출 정책 검증

2026-11-17. Windows에서 JS 정책·자동 검사·브라우저 안내·30일 모델을 검증했다. 실제 AdMob/UMP/StoreKit 연결은 미완료이며 Mac에서 이어서 구현한다.

## 적용 정책

- 보급 해금: 첫 파츠 합성 또는 프레스티지 이후.
- 보급 광석: 요청 시점 `max(채굴량/초 × 120, 다음 스킬 뽑기 비용 × 0.20)`을 최종 내림하고 안전한 광석 보유 여유만큼 제한한다. 버튼에 실제 지급 견적을 표시한다.
- SDK 보상 획득 콜백과 고유한 광고 ID가 확인된 경우에만 지급한다. 요청 이후 능력치 변화로 보상이 바뀌지 않는다. 완료 후 5분 대기와 최근 ID를 저장한다.
- 보급은 전경 채굴·모듈·캠페인 활동 과제에 포함하지 않는다. 광고 없이 모든 과제를 완료할 수 있다.
- 전면 광고: 앱 실행 후 전경 플레이 10분 이후, 전경 플레이 8분 간격, 실행당 성공 노출 최대 2회. 백그라운드와 SDK 처리 시간은 전경 시계에 포함하지 않는다. 서비스 재초기화는 시계/횟수를 초기화하지 않는다.
- 프레스티지 후 전경 15초 안에서 보상 카드·튜토리얼·대화상자가 사라진 때 한 번만 시도한다. 만료·백그라운드·저장 복원·보급 요청은 대기 기회를 취소한다.
- 보급 완료 후 2분간 전면 광고를 막는다. no-fill/실패는 성공 노출 횟수를 사용하지 않으며 전경 60초 동안 재시도를 막는다.
- 광고 중 게임 진행과 게임 효과음을 중단하고 복귀 프레임 시간을 초기화한다. 광고 소리는 기기/광고 SDK 영역이다.
- 광고 제거 IAP는 전면 광고만 제거한다. 선택형 보급은 유지하며, 구매 권한과 UMP 허용은 네이티브 결과로만 적용한다.

구현: `web-prototype/platform/catalog.js`, `services.js`, `interstitial-window.js`, `web-prototype/app.js`.

## 30일 모델

실행: `npm run balance:ads`. 원본: `tools/reports/monetization-monthly.json`.
정책별 20시드, 1초 간격, 30일, 4시간 오프라인 상한, 기존 출시 모델과 같은 과제 수령/강화/모듈 선택을 사용한다.
표준은 하루 2회 × 6분, 집중은 하루 2회 × 15분이다. 매 방문에 새 플랫폼 서비스를 만들고 앱 실행으로 취급한다.
광고 한 편의 30초를 고정된 접속 시간 안에서 차감하며 그동안 채굴·전투는 멈춘다. 모든 광고가 준비되고 끝까지 시청된다고 가정하며 IAP는 없다.
전면 광고 기회는 환생 후 전경 5초로 근사한다. 추가 튜토리얼/카드 지연은 모델에 없다.
기존 빈도 비교도 동일한 첫 합성 해금을 적용하므로 과거 구현 전체의 재현은 아니다.

표의 광고 수와 광고 시간은 30일 누적 중앙값이다. 완주일 중앙값은 완주한 시드만 대상으로 한다.

120초 채굴량만 지급하면 표준 모델에서 다음 뽑기 비용의 평균 약 2.6%에 불과했다. 20% 하한을 적용한 출시 정책은 약 21.3%이고, 보급 직후 뽑기를 할 수 있는 수령 비율이 약 3.3%에서 18.3%로 올랐다.
이 비율은 시드별 수령 통계를 계산한 뒤 중앙값을 취한 값이며, 뽑기 비용 대비 개별 지급 비율은 100% 상한으로 집계했다.

## 판단과 한계

짧은 세션에서는 강제 전면 광고가 없고 무광고 캠페인 완주 경로를 보존한다. 보급은 광석 뽑기를 돕지만 시청으로 전투·전경 채굴 시간이 줄기 때문에 전체 완주가 항상 빨라지지는 않는다. 표준 모델은 무광고보다 약 하루 느렸다.
집중 모델에서 보급을 매번 받으면 약 10.5일로 짧아지므로, 실제 사용자 완주 속도와 보급 선택률을 확인하고 후반 콘텐츠/수치를 재검토해야 한다. 날짜 잠금이나 광고 의무 조건은 추가하지 않는다.
전면 광고 제거 가치는 긴 세션에 집중된다. 짧은 세션 위주 사용자의 구매 동기·서포터 외형 선호도는 아직 검증하지 않았다.
실제 광고 길이·준비율·동의 거부·사용자 선택·피로도·리텐션·수익은 모델로 입증할 수 없다. 이 결과를 실측 사용자 지표나 수익 예측으로 쓰지 않는다.

## 검증과 남은 작업

- `npm run check`: 해금·완료/중복/대기 저장·수치 한도·요청 시점 견적·과제 제외·전경 시계·정확한 시간 경계·횟수·실패 재시도·카드 대기/만료/취소 검증.
- 한영일 공통 430키 검사. 320px 브라우저에서 광고 도움말의 세 언어와 설정 가로 넘침 없음 확인. 미지원 브라우저의 보급 버튼 숨김과 콘솔 오류 없음 확인.
- 실제 SDK·iPhone 광고 중단/복귀·오디오·no-fill·UMP·구매 제거 검증은 `MAC_HANDOFF.md`에 기록했다. 네이티브가 없는 브라우저에 광고/구매 성공 경로를 만들지 않았다.
- 원어민 문구 검수와 실제 사용자 플레이테스트, 리텐션/광고 수용성/구매 가치 검증은 미완료다.
