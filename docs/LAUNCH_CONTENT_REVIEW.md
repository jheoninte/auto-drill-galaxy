# Gemini 출시 콘텐츠 통합·검증

2026-11-17 사용자 전달 초안을 검토해 기존 Vite/Capacitor 프로젝트에 통합했다.
초안 원문 데이터/아트 방향/검토문은 `tools/handoffs/gemini-release-draft/`에 보관한다.
함께 제시된 단일 HTML/HubGame 저장·리더보드는 채택하지 않았다. 기존 세이브 복구·네이티브 구매 경계·i18n을 유지한다.
Gemini가 언급한 외부 스킬 실행 여부를 이 저장소에서 확인한 것으로 취급하지 않는다.

## 실제 연결된 내용

- 5구역 × 6개 순차 과제. 시작부터 캠페인을 열고 구역별 카드/선택/보상 수령/메인 목표를 제공한다.
- 스킬 12→18, 연계 3→6. 새 스킬 6종은 첫 프레스티지 후 광석 뽑기에 들어간다.
- 보스 3→5 원형/각 2단계. 기존 W5~30 순환은 보존하고 W35 중력, W40 항성부터 추가 순환한다.
- 영구 연구 2→4종/각 5단계. 치명타 피해 배율 가산(+최대 0.25, 기본 2.2배)과 웨이브 광석 보상(+최대 30%)을 연결했다.
- 무료 빔/궤도 7→15종. 추가 8개는 캠페인 12/18/23/24/28/29/30개 수령 시 해금하며 마지막 과제에서 2개를 받는다.
- 서포터 색상 3종 선택. 저장에는 선택 취향만 두고 실제 네이티브 권한이 없으면 색상을 적용/선택하지 않는다.
- 구역별 배경 색조/별 강조색, 보스 원형별 변 수를 현재 Canvas 표현에 반영했다.
  최종 그래픽/아이콘 76개 전체 제작 완료는 아니다.
- 캠페인/새 데이터는 한영일 문구를 연결했다. 공통 UI 키는 247개로 늘었다.
  Gemini UI 초안은 언어별 51개뿐이므로 기존 188개 카탈로그를 덮어쓰지 않았다.
  기존 연구소·탐사·시스템/SDK 오류의 남은 현지화는 계속 필요하다.

## 원안에서 수정한 부분

1. 초반 1·2과제 보상을 각각 광석 10개로 줄였다. 첫 합성 전에 철/수정 보상으로 초반 검증 구간을 건너뛰지 않게 했다.
2. 구역마다 1부터 반복되던 `order`를 캠페인 전체 1~30으로 정규화했다.
3. 연계 1개/3개 과제에 보스 누적 20/35기라는 결정적 대체 조건을 추가했다. N/R 스킬도 무작위이므로 필수 뽑기 운에 묶지 않는다.
4. 캠페인 모듈 누적은 항로 해금과 별도로 집계한다. 원안의 기존 항로 카운터 재사용만으로는 초반 모듈 과제 집계가 늦어진다.
5. 최종 외형의 W45 조건을 전체 캠페인 완주 보상으로 바꿨다. 한 달 분량 안에 15개 외형 모두 획득 가능하다.
6. 첫 모델에서 14일에 29/30이 끝나고 마지막 웨이브만 기다리는 문제가 있어 마지막 구역을 재배치했다.
   환생 30회 / 전경 채굴 160만 / 스킬 중복 포함 84개 / 연구 합계 20레벨 / 보스 175기 / 최고 W40으로 조정했다.
7. 같은 약점 모듈에 해당하는 연계가 둘이어도 피해 보너스는 합계 +0.10으로 제한한다. 모듈 약점 +0.25는 기존대로 별도다.
8. 추가 연구의 치명타 확률 보너스는 기존 65% 상한에서 무의미해져 치명타 피해 배율 보너스로 변경했다.
9. 서포터 문구를 색상 3종에 맞췄다. 상품 ID/현지화 가격/검증/복원은 기존 네이티브 계약을 따른다.

## 저장·집계 경계

`prestige.campaign`에 순차 `claimed`와 `drillOre/lanceKills/syncBosses`만 저장한다.
웨이브·환생·스킬·합성·연구·활성 연계는 기존 영구 상태에서 계산한다.
전경 채굴/보스는 기존 탐사 카운터를 사용한다. 캠페인 수령 기록은 연속 prefix로 정규화한다.
일반 재료 보상·광고·오프라인 채굴은 모듈 과제에 포함하지 않는다. 구매하지 않은 모듈도 집계하지 않는다.
프레스티지는 캠페인 진행/수령/외형을 유지한다. 기존 저장은 알고 있는 항로 카운터를 보존해 이전한다.
이전에 집계하지 않았던 모듈 기록을 새로 만들어 소급 지급하지 않는다. 다른 백업 복원은 기존처럼 진행 전체를 교체한다.

## 30일 무광고·무과금 모델

`npm run balance:launch`, `tools/reports/launch-monthly.json`. 각 조건 20시드, 1초 단위.
현재 과제가 요구하는 모듈을 구입/선택하고 그 외에는 전투 모듈을 사용한다.
매초 뽑기·합성·연구·보상 수령을 수행하고 해금 웨이브에서 즉시 프레스티지한다.
부재 시 채굴만 최대 4시간 정산한다. 실제 사용자 판단 속도를 측정한 결과는 아니다.

| 조건 | 30일 내 완주 | 완주자 중앙 시점 | 30일 완료 과제 중앙값 |
| --- | --- | --- | --- |
| 표준: 하루 2회 × 6분 | 20/20 | 약 23.00일 | 30/30 |
| 가벼운 접속: 하루 1회 × 5분 | 0/20 | 미도달 | 23/30 |
| 집중: 하루 2회 × 15분 | 20/20 | 약 14.51일 | 30/30 |

표준의 1/3/7/14/21/30일 과제 중앙값은 7/11/17/24/28/30개다.
모든 사용자에게 30일이 걸리도록 날짜 잠금을 걸지 않는다. 적게 접속하면 더 오래 걸린다.
첫 합성 중앙값 217초. 연속 15분 세션 모델의 첫 환생 해금 중앙값은 686초(약 11.4분)다.
표준의 해금까지 전경 시간 509초는 중간 12시간 부재의 채굴 보상이 포함되므로 연속 플레이 시간과 비교하지 않는다.
기존 과제 미수령 모델 `npm run balance`는 첫 합성 218초/환생 해금 764.5초로 초반 기준을 유지한다.

이 모델은 약 한 달 분량의 진행 가능성과 막힘을 확인한다. 재미·잔존율·광고 시청·결제 전환을 증명하지 않는다.
남은 검증: 모듈 선택을 자주 하지 않는 사람의 안내 이해도, 수령 버튼 반복 피로,
한영일 전체 동적 문구, 실제 플레이 속도/경제, iPhone 발열·저장·오디오·SDK 통합.

`npm run balance:month`는 현재 성장 데이터로 캠페인 보상을 수령하지 않는 모듈별 비교다.
출력은 `monthly-without-campaign.json`이며 과거 `monthly-baseline.json`은 덮어쓰지 않는다.


## 최종 회귀·화면 확인

- `npm run check`, `npm run balance`, `npm run build` 통과. Vite 40개 모듈, JS 약 149KB(압축 약 48KB).
- 초기 캠페인 접근/첫 보상 수령/다음 목표/중복 수령 차단을 실제 브라우저에서 확인했다.
- 검증된 테스트 백업을 UI로 복원해 마지막 6과제를 수령하고 30/30 완주, 마지막 외형 2개 지급과 적용을 확인했다.
- 영어 최종 외형 설명에서 과거 W45 조건을 제거했음을 확인했다. 일본어 5구역/최종 과제/완주 보상도 확인했다.
- 320×740에서 캠페인 대화상자 clientWidth와 scrollWidth 모두 250px로 가로 넘침이 없었다.
  일본어 완주 화면 기록은 저장소 루트 `campaign-preview.jpg`다. 세로 스크롤은 유지한다.
- 네이티브 권한 없는 브라우저에서 구매와 유료 선체 3색 선택은 비활성 상태다.
- 테스트 주소 4177만 사용했다. 고급 테스트 후 원래 테스트 백업으로 복원하고 임시 탭/서버를 정리했다.
  기존 사용자 주소 4174의 플레이 저장은 조작하지 않았다. 최종 재로딩 이후 캡처된 콘솔 오류는 없었다.

이 검증은 Windows 웹 구현에 대한 결과다. 네이티브 StoreKit/AdMob/UMP 연결과 iPhone 검증은 아직 완료되지 않았다.
