# 연구소 구현 및 Gemini 협업 기록

이후 추가한 항해 계약/영구 목표 및 반복 환생 목표 상승 규칙은 `EXPEDITION_REVIEW.md`를 기준으로 한다.

2026-11-17, 실행 중인 Gemini Windows 앱의 기존 게임 전용 대화에서 설계 검토를 요청하고 답변을 수신했다.
대화: https://gemini.google.com/u/1/gem/78b48bcfc4c2/c20e1ae511782b11
Gemini는 기획/대안 비교/파라미터 초안/악용 검토를 맡았고 Codex는 기존 코드 통합과 실제 시뮬레이션을 맡았다.
앱에는 Pro 한도 안내가 있었으며 응답 이후 모드 표시는 `4 Hydrogen`이었다. 특정 Pro 모델의 결과라고 간주하지 않는다.

## 채택 및 조정

- 채택: 항해 모듈 3종 중 1개 활성화, 각 3단계, 플라스마 지출. 영구 연구 2종 각 5단계, 유물 지출.
- 채택: 모듈마다 단계 독립 저장, 10초 전환 대기, 환불 없음. 프레스티지 시 모듈/플라스마 초기화, 유물과 연구는 유지.
- 조정: Gemini는 Wave 5 보스 이후 사용 가능하다고 제안했지만 첫 합성 시점 보호를 위해 엔진 2 이상 또는 프레스티지 경험 후 해금한다.
- 조정: 모듈 치명타 추가 보너스는 제외. 모듈 배율은 기본 파츠 채굴/공격에만 적용한다.
- 조정: 영구 연구는 Gemini의 채굴 최대 +4.5/초, 공격 최대 +14/초에서 각각 +1.5/초, +3/초로 낮췄다.
- 전환 대기는 실제 전경 플레이 시간으로만 감소하며 저장/불러오기로 건너뛸 수 없다. 백그라운드 동안도 대기는 유지된다.
- 최초 모듈 강화 시 활성 모듈이 없고 대기가 없다면 자동 적용한다. 그 외 강화는 현재 모듈 선택을 바꾸지 않는다.

## 데이터와 공식

데이터 원본은 `web-prototype/game/workshop.js`. levels 항목은 누적 효과이며 costs는 다음 단계 1회의 지불 금액이다.

| 모듈 | 단계별 플라스마 비용 | 파츠 채굴 효과 (Lv1/2/3) | 파츠 공격 효과 (Lv1/2/3) |
| --- | --- | --- | --- |
| 채굴 과부하 코어 | 2 / 5 / 10 | +25 / +50 / +85% | -10 / -15 / -20% |
| 궤도 플라스마 창 | 2 / 5 / 10 | -10 / -15 / -20% | +30 / +60 / +100% |
| 양자 동기화 엔진 | 3 / 7 / 14 | +15 / +30 / +50% | +15 / +30 / +50% |

영구 연구는 모두 유물 1/2/4/7/12 비용이며 채굴 +0.25/0.5/0.75/1/1.5, 공격 +0.5/1/1.5/2/3을 제공한다.

```text
채굴 = (기존 파츠 기본값 + 스킬 합) * (1 + DM효과)
       + 기존 파츠 기본값 * 활성 모듈 채굴 효과 + 영구 연구 채굴값
공격 = (기존 파츠 기본값 + 스킬 합) * (1 + DM효과)
       + 기존 파츠 기본값 * 활성 모듈 공격 효과 + 영구 연구 공격값
```

기존 값에 반복 곱셈하지 않고 매번 원본 파츠/스킬/연구 단계에서 재계산한다. 비활성 모듈 효과는 중첩되지 않는다.

## 실측 검증

`npm run balance`: 동일 시드 1~20, 0.25초 간격, 광고 없음, 가능한 즉시 가챠/합성.
모듈 비교는 첫 합성 이후 선택한 모듈만 가능한 즉시 강화하고 유물은 탐지기 우선, 안정화 다음 순서로 소비했다.
프레스티지는 실행하지 않고 해금 시점을 측정했다. 아래는 각 분포의 상위 중앙값이며 모든 유저의 시간을 보장하지 않는다.

| 선택 | 첫 합성 | 첫 프레스티지 해금 |
| --- | --- | --- |
| 연구소 미사용 | 218초 | 770.75초 |
| 채굴 | 218초 | 792.5초 |
| 전투 | 218초 | 703.25초 |
| 균형 | 218초 | 748.25초 |

연구소 시뮬레이션과 별도로 잠금/재료 부족/알 수 없는 id/최대 단계에서 무지출, 모듈 독립성, 재접속 대기,
구형·비정상 필드 세이브 이전, 프레스티지 유물·연구 유지/모듈 초기화, 오프라인 보상 중복 정산 방지를 검사한다.
오프라인 보상은 저장된 모듈 상태로 앱 로드/전경 복귀 때 UI 조작보다 먼저 정산한다. 이후 전환은 이미 정산한 보상에 영향을 주지 않는다.
이는 서버 검증이나 로컬 세이브 변조 방지 기능은 아니다.

모바일 브라우저에서 강화 시 재료 차감, 채굴/공격 변화, 비활성 모듈 강화, 무료 전환 및 재접속 후 연구 유지 확인.
iPhone 실기기, 장기 경제 및 네이티브 IAP/IAA SDK 검증은 아직 필요하다.
