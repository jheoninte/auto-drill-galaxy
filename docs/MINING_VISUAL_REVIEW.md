# 행성 채굴 연출

2026-11-17 사용자 참고 이미지의 핵심인 ‘실제로 표면이 깎이는 채굴’을 현재 Canvas 장면에 구현했다.

- 원형 행성을 613개 블록으로 구성하고 `asteroidHp / maxAsteroidHp`에 따라 오른쪽부터 제거한다. 단순히 행성 전체를 축소하지 않는다.
- 남은 블록의 외곽선과 광맥을 그려 파인 단면을 표시하고, 원래 행성 범위는 희미한 점선으로 남긴다.
- 채굴 빔과 함선 방향은 현재 제거할 블록의 표면을 겨냥한다. 함선은 파인 쪽에서 작은 호를 따라 움직인다.
- 제거 지점에서 짧은 파편을 내보내고 빔 접점이 작게 맥동한다. 파편은 최대 72개, 프레임당 생성은 제거 블록 최대 8개로 제한한다.
- 웨이브/환생 변경·리사이즈는 파편을 비운다. 저장에 연출 상태를 추가하지 않으며 복귀 시 현재 HP에서 즉시 형태를 재구성한다.
- 모션 줄이기에서는 함선 이동·파편·접점 맥동·격파 파동을 끈다. 체력에 따른 파임과 정적 빔은 유지한다.
- 보스의 단계별 고리, 구역 강조색, 무료 항로의 빔/궤도, 네이티브 구매 권한 기반 함선 색상을 유지한다. 보스 개별 문양 아트는 후속이다.

구현은 `web-prototype/ui/planet.js`, `scene.js`와 장면 높이 CSS에 한정한다. 채굴·전투 수식, 재화 지급, 저장 스키마는 바꾸지 않았다. 블록은 시각화 단위이며 개별 블록을 재화 보상 횟수로 쓰지 않는다.

검증:

- 전체 613개 파괴 경계를 순회하여 남은 코어의 연결성을 확인했다. HP 100%/0%에서 전체 유지/제거, 유한한 빔 좌표, 모션 줄이기와 렌더러의 게임 상태 비변경도 검사했다.
- 390×844 및 320×740 브라우저에서 파인 행성과 빔 접점을 확인했다. 가로 넘침과 콘솔 오류는 없었다.
- 기존 자동 검사와 Vite 출시 빌드 통과. iPhone 실제 프레임·발열·장시간 메모리는 Mac에서 확인해야 한다.

재현 화면: 저장소 루트 `planet-mining-preview.jpg`. 별도 테스트 포트에서 확인했으며 사용자의 플레이 저장을 초기화하지 않았다.
